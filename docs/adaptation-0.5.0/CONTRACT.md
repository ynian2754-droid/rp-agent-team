## Product turn contract (public Conversations API)

Names are PoC names, not promises about upstream naming. Add methods to the existing product API; do not create a new bridging Service.

`currentTurn({ conversationId?, sessionId? })` returns null until the matching prepared product operation has a durable user input and an active native turn; otherwise `{ conversationId, sessionId, operationId, turn, inputMessageId, inputEventSeq, worldHash, model? }`. Both identifiers, if supplied, must match. Input identity comes from official Session/input projections. The native `agent/request` hook occurs before input persistence, so it selects a delivery route; admission and freezing occur at its stream boundary. No filesystem paths/internal snapshot objects. `worldHash` covers current variables and the complete raw editable setting library, including null; runtime-expanded prompt text is not the CAS baseline. Existing `authorState`, `details`, model/preset and Session APIs provide actual data.

`stageTurnState({ conversationId, operationId, runId, expectedWorldHash, variableStateJson?, settingLibrary?, inputMessageId?, localDelivery? })` returns a receipt with `outcome: 'pending'`. `settingLibrary` is the existing public SettingLibrary type. `localDelivery` is an optional `{ provider, model }` marker identifying the plugin's non-network final-delivery request. It must not change the user's model selection or impersonate provider usage. Accepted staged data has undergone product author-schema validation and baseline checking; it is consumed only by that operation's normal product save. A run ID belongs to one operation. Identical retries are idempotent; changed payload under the same identity is rejected. Independent author changes after preparation conflict. Failure/cancel discards pending data; output/save failure must never be reported as committed.

`turnCommitStatus({ conversationId, runId })` returns `{ outcome: 'pending'|'committed'|'failed'|'cancelled'|'unknown', conversationId, runId, operationId?, sessionId?, turn?, inputMessageId?, assistantMessageId?, assistantSeq?, baseHash?, active?, error? }`. Results are durable across processes; `active` says whether a committed output still belongs to the effective branch. Native Session flush precedes the product transaction; product variables/settings, runtime checkpoint and receipt are committed consistently. Plugin state is outside this transaction. Unknown results never automatically re-run models. Do not persist model credentials or reasoning in receipts.

The plugin journals its staged shared/private state, commits only on `committed && active !== false`, and reconciles checkpoints against official input/output identities after rewind/retry/restart. A publishing run whose stage call may have crossed the Host boundary is unresolved even if its acknowledgement has not returned; pending/unknown must block a new run until durable settlement. Normal DSH run-end is insufficient evidence of successful product save.

Author edits: the existing editor promises CAS, world variable/setting edits, durable status and historical restoration. `replaceVariableState` cannot meet CAS/checkpoint semantics. Add narrow `editCurrentState({conversationId, operationId, expectedWorldHash, anchor?, variableStateJson?, settingLibrary?}) -> {outcome, operationId, baseHash, revision, anchor}` and `stateEditStatus({conversationId,operationId})`, reusing existing author validation/setting-library save implementation, rejecting active generation or changed baseline. Store the receipt with the product state mutation transaction. `listStateEdits({conversationId})` supplies public historical world before/after snapshots, anchor and revision, without SQL/internal objects, for the existing author checkpoint UI. Plugin validates its definitions and ACL, journals its own edits and uses the receipt for restart reconciliation. Restore is another explicit editCurrentState with current baseline and selected historical values; no separate rewind callback or restore Service. Use official effective-branch output identities to determine applicability. Do not recreate begin/endConversationWork or expose a database handle. World hash is SHA256 of recursively key-sorted JSON `{ variables: parsedCurrentVariableState, settingLibrary: effectiveSettingLibrary }`; arrays retain order.

## Import contract

Add `importArchiveWithMapping(characterId, json)` alongside the existing string-returning API, reusing the same implementation. Return `{ conversationId, sessions: Record<oldId,newId>, messages: Record<oldId,newId>, operations: Record<oldId,newId> }` (retained message IDs map to themselves). Mapping is exact and includes parents/children; no timestamp inference. Imported operation IDs are newly allocated, including receipt references, because they are globally unique product identities and a source may already exist in the target database. The durable import journal returns the same mapping on repeated import. Archive fields necessary for historical runtime checkpoints/attachments and explicitly referenced native Session logs are public and versioned. Import creates a fresh official schema; never change an old patched schema10 in place. The clean target starts at schema9 and the supplement introduces its own schema10 with different contents.

Host conversion scripts own product export/import, check-point and receipt conversion; plugin conversion owns config/run/state/trace association remapping. No runtime plugin SQL access. Preserve Agent/preset IDs and state values. Unknown legacy associations remain archived. Import journal keys prevent duplicate product content on retries after journaling. Session flush and SQLite are separate stores: a hard process interruption between them may leave orphan Session files, and cross-store atomicity is not claimed. Plugin conversion reuse requires both the mapping hash and the signature of consumed source files to match; changed inputs require a new empty destination.

## Direct runtime and trial boundaries

DSH event hooks and Agent/Team/Subagent/Session APIs own members, models, tools, cancellation, budgets and local final delivery. Product data is frozen then projected per member; actual requests, nested calls and compaction must not expose unauthorized fields. Product tools remain unavailable to Team members, but normal RP retains them. Scope disposal drains running work.

The product Agent Preset catalog and the DSH native Agent preset registry are distinct identity spaces. A member's `presetId` selects an actual registered DSH composition; a product preset imported through the product API is not automatically such a composition. Trials freeze the product preset for the root chat separately from explicit native member definitions. They must not substitute a newly imported product ID for a native member ID. Per-member compaction definitions are plugin-owned, content-addressed native compositions; register them before restoring Agents, select them through the public DSH preset API, and preserve definitions in private plugin data for cold restoration.

Trial frozen data is plugin-owned JSON with an official conversation archive, character/config dependencies, attachment descriptors/content, model routes/provider settings without secrets, and referenced Agent presets. Worker credentials travel through the existing protected IPC/DSH credential flow, not the snapshot. Worker boot uses `@eleckoi/desktop-host` public boot/bundle exports, not old `@eleckoi/dsh-runtime` or source-tree resource paths. A/B each import from the same snapshot into isolated spaces. Trial worker uses the same runtime and turn commit contract. Each successful checkpoint preserves an official archive plus plugin committed state; retries resume only committed checkpoints in a fresh Host-owned worker generation. Session evidence retains its generation, so completed variants and old failed attempts continue to refer to their original profiles. Unknown commit outcomes prohibit blind retry.

## Frontend contract

Cold trial receipt recovery reads the original worker generation through the official Host runner, never importing into or prompting that profile. The product conversation details supply the canonical root Session identity; an in-memory binding may be absent after restart. A committed receipt must explicitly be active and match the original input identity/sequence and saved assistant identity/sequence. Captured native preset documents are restored through the official registry only when missing; conflicting registrations are not overwritten. Per-trial in-flight recovery is shared across concurrent retries. Pending/unknown remains unresolved. A successful reconciliation persists the original turn checkpoint without model dispatch; explicit retry resumes remaining steps in a fresh generation.

Keep existing right workspace and configuration editor. Replace old Trajectory Service with a plugin-owned official conversation view/trajectory Slot, use `sessions.retain` and `uiConversation` for real child events, reuse publicly loadable trajectory components. Root owns navigation by official view-selection API, never DOM clicks. Trial embeds the same view. Stable identity is session+event/call, run+traceSeq, executionId; no title-string matching. Member prompts belong in request details. Run/current-attempt groups remain structured, not fabricated context rows. Credentials and private reasoning are excluded; observable results and provider-visible public summaries remain inspectable.
