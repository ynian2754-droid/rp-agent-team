# 作者使用变化

试演被中断后，会在原独立运行空间查询正式回执。确认已保存的那一轮恢复原正文和检查点，随后明确重试才继续剩余输入；不会重跑已保存的一轮。结果仍未知时继续保留记录并阻止重跑。若同名原生成员预设内容不符，不覆盖它来强行恢复。

0.5.0 保持 schemaVersion 2。成员、触发、Context、通信与 handoff、状态 ACL、输出权、执行限制、参数、记忆和预算的语义不因宿主迁移改变。名称仍只是作者语义，框架不会把“主笔”“记忆”等名称解释为特殊类型。

团队成员继续使用 `rp_team_read_context`、`rp_team_search_context`、`rp_team_read_attachment` 及 Team 状态/记忆工具，不重新开放 ElecKoi 产品工具。挂载原生 preset 的作者应检查它是否要求旧 eleckoi_* 工具；旧提示词不会被自动改写。普通聊天仍使用原有工具。

每轮在真实用户输入进入官方 Agent Loop 时冻结配置、模型和资料。发布者正文通过本地交付路由进入同一正式 Session，不额外调用模型改写。共享、私有和世界状态先暂存，只有产品回合得到持久 committed 结果才正式提交。unknown/pending 表示尚不能确认，不能自动再跑一次模型。

世界状态和作者编辑通过公开产品 API 校验、CAS 和事务保存，插件不打开产品 SQLite。回退以官方有效分支的输入/正文身份判断，原生事件序号仅在同一 Session 内定位。预设 ID、Agent ID 与聊天 ID 是不同概念。

轨迹的尝试/成员分组属于插件；真实模型、工具、压缩和错误记录来自原生 Session。当前尝试展开，旧尝试保留。启动资料移到请求详情，调度和状态事件留在协作详情。实际请求输入可以持久检查，凭据和私有推理块不进入插件证据存储。本地正文交付不计外部模型调用或虚构 token。

试演使用公开角色/聊天归档、附件、模型和 preset API 冻结资料，再用公开 Desktop Host 启动独立进程和数据空间。A/B 各自导入同一起点；检查点具有独立内容身份，A 不能覆盖 B 的初始快照。凭据通过保护的运行通道提供，不进入分享文件。采用试演方案只加载配置/参数草稿，不带回正文或积累状态。

试演中的步骤编号与 DSH 原生 turn 分别记录。已确认失败后显式重试会建立新的隔离 profile，并从最后已提交检查点继续；已完成的比较方案不重新运行，旧失败尝试仍可检查。未能确认是否提交时，不能用重试代替持久结果核对。

原生 preset 与其来源 bundle 之间的精确依赖关系目前不属于官方 preset DTO 的明确字段。试演保留可取得的 preset 配置及能够确认、具有可安装包引用的依赖。无法确认来源的第三方扩展工具组会在启动前报告缺失依赖并停止，不会默默移除工具后继续试演。不能把“保存了 preset 文本”当成全部外部工具也已自动复制。
