# RP Agent Team 0.4.0：给创作者的使用说明

这版增加试演、使用参数、事件触发、记忆集合和资源预算。成员仍由你自己定义：它可以是人物的注意力、偏见、身体感觉、回忆，也可以是世界或 NPC。软件不会要求你一定推进剧情。

## 先预览，再试演

“预览”只检查配置，不请求模型，也不改变聊天。“试演”会实际请求你选定的模型，所以需要你点击“开始试演”。开发验收用的是本地可控模型；日常使用你自己的模型时，仍会产生它的正常用量。

进入“试演”，填写场景名称和连续几轮的用户输入。软件不会替你编造用户行为。可以为每轮添加检查项：正文包含或不包含某句话、某状态等于指定值、只保存一条正文。这些检查不会评价哪种扮演更正确。

点击“冻结当前聊天资料”，把所选聊天需要的角色、历史、附件和状态固定下来。试演在独立进程、独立数据库、独立会话和工作目录中运行。后续正式聊天的变化不会偷偷进入已经冻结的试演。重新冻结会明确更换资料快照。

默认方案 A 使用当前草稿和使用参数；可从预设库选一个方案 B。两个方案依次从同一份资料开始，A 写出的正文、记忆和状态不会进入 B。结果展示正文、状态、成员运行、耗时和实际用量，轨迹入口使用主聊天原有的搜索、工具详情和模型请求查看界面。

关闭页面不会停止任务。要停止，请使用任务上的停止按钮；软件会取消并排空在途执行。进程中断会被标记为“中断”，只有你明确重试才继续，从最后已经提交的试演轮次之后开始。启动结果未知时先查询任务，必要时重新提交同一个启动请求，不会自动创建第二个任务。

停止或中断后，已经发生的请求仍占用整个任务的预算。若某个请求没有返回完整用量，开启 Token 预算的原任务会显示“用量不可计量”并阻止继续调用；保留已提交结果及失败尝试的轨迹，不把未知用量当成零。

场景、结果、轨迹和恢复检查点保存在插件自己的数据目录。原生试演进程的工作文件使用系统临时目录内独立的 `rpt` 文件夹，避免 Windows 深层路径限制；每个任务和方案使用不同目录。恢复依据插件保存的检查点重新建立空间，不依赖临时目录永远存在。

“采用这个方案”只把配置与参数载入正式聊天草稿。保存后下一轮生效；试演正文和积累的状态不会复制回来。

默认只开放托管工具和试演工作目录。若本次明确开启外部工具信任，工具访问外部文件、网络或程序产生的影响不属于试演数据隔离范围。

## 把复杂配置包装成使用参数

在“团队设置 → 使用参数”调整作者公开的选项，例如表达倾向、某成员的模型、温度、周期或初始状态。某个聊天的参数值独立保存，不改写分享预设的默认值。

作者打开“定义使用参数”，通过表单填写名称、说明、类型、默认值、取值要求和绑定目标。支持文字、数字、开关、选项、成员、模型和状态位置。成员绑定使用稳定成员 ID，删改排序不会把参数绑到另一个人。

文字插入模式需要在目标提示词中放入 `{{param:参数ID}}`，再把参数绑定到那段提示词。直接设置模式可以控制已有配置字段；高级绑定允许指定字段位置和参数中的某个部分。它不会执行代码。

实际改动会在面板里列出，包括权限变化。缺失模型、成员或状态引用会保留并提示修正，不能静默换成别的选项。每一轮固定本轮使用值和解析后的配置；轮次开始后修改草稿不会影响已经开始的执行。

分享预设和组件会包含参数声明、默认值和依赖。不会携带聊天里的使用值、凭据或运行记录。组件导入重新分配成员 ID 时，会同步更新参数绑定和提示词标记。

## 事件与节奏

成员的“触发”新增四种规则，可与原有规则组合：

- 每隔 N 轮：按当前有效聊天分支的用户轮次计算，不按轨迹事件编号计算。
- 状态变化：比较真正记录下来的前后值；没有可靠旧值时显示无法判断，不猜测。
- 收到消息：筛选来源成员、消息类型和主题；仍受通信与上下文权限约束。
- 输入关键词：当前输入包含任一或全部指定词，支持区分大小写；成员必须有权读取当前输入。

冷却轮数表示成功触发后跳过接下来的指定轮数。例如冷却 2 轮，在第 3 轮执行后，第 4、5 轮不会因为同一规则再执行。冷却只在正文成功提交后生效，失败和取消不消耗冷却；回退会恢复有效分支的记录。明确重试可以越过冷却，仍须满足权限、预算和执行次数限制。

同一事件不会重复启动成员；消息请求、交接和事件触发会合并已有调度理由。编辑状态不会立即后台调用模型，只在下一次你主动开始聊天或试演时检查。

## 记忆集合

先定义一个“列表”状态，再在“记忆集合”中选择它的位置。集合可以放在共享、成员私有或世界状态里，继续使用已有读取、写入权限和提交、回退规则。

成员可使用五个工具：`rp_team_memory_search`、`rp_team_memory_add`、`rp_team_memory_update`、`rp_team_memory_archive`、`rp_team_memory_restore`。搜索支持内容关键词、人物、标签、来源、时间、作者字段、排序和数量。先排除无权查看的记录和字段，再搜索和统计；隐藏内容不会因为搜索数量而露出来。

每条记忆有稳定 ID、内容和时间。视角、可信程度、人物、标签、来源及自定义字段可选。你可以把客观事实、角色信念和主观回忆放在不同集合；软件不会自动把误解修正为真相，也不会偷偷请求模型整理记忆。

修改需要对应状态的写权限和状态输出权限，还需要工具返回的版本号。更新工具一次修改一个字段，避免覆盖成员看不到的字段；并行修改冲突会明确失败。正式聊天失败时本轮暂存修改会丢弃，成功正文提交后才持久保存，回退恢复对应检查点。

“当前状态”提供集合查看、筛选、编辑、归档和恢复。分享预设只带集合定义和作者初始值，不自动携带聊天中积累的记忆。

## 预算

在执行限制旁，可以填写模型调用次数、已报告 token 阈值和最长耗时。正式聊天留空表示不开启新增限制，保留旧行为。托管成员、嵌套调用和压缩请求都计入，最后的本地正文交付不算外部模型请求。

调用名额在派发之前统一占用，避免并行请求超发。耗时包括等待交接。token 只使用服务商实际报告的用量，按请求身份去重；开启 token 阈值但服务商不报告用量时，会停止后续调用并显示“用量不可计量”。

达到阈值会停止本轮，取消在途执行，保留轨迹，丢弃本轮正文和暂存状态。此前成功轮次不受影响。不会自动重试、换模型或追加正文。在途请求仍可能报告更多用量，所以 token 阈值不是精确费用封顶。

试演默认每轮最多 32 次调用、64,000 个已报告 token、180 秒；整个任务最多 64 次调用、128,000 个 token、600 秒。可在开始前修改。页面会展示输入轮数、方案数量和整个任务范围。

## 分享与安装

`examples/v040/usage-memory.rp-team.json` 展示可调语气和角色回忆；`neutral-trial.rp-trial.json` 是三轮作者输入的试演场景。场景默认导出输入与检查项；只有明确勾选“包含冻结资料”才导出所选历史、附件及状态。凭据始终排除。

配置格式仍为 schemaVersion 2。使用新增能力的分享文件声明最低插件版本 0.4.0。支持的宿主仍是附带累计补丁的 ElecKoi v0.2.4 固定基线；产品数据库保持版本 10，不需要重新迁移聊天。
