# RP Agent Team 用户手册

RP Agent Team 是 ElecKoi 的可选增强。日常使用仍然是普通聊天；打开团队后，多个独立成员可以按各自可见的信息、触发规则、工具和权限协作，本轮仍只由获准的发布者向角色聊天交付一条正文。

适用版本：插件 0.4.1，ElecKoi v0.2.4 固定版本，DSH 0.2.0-rc.2。请先按[安装与更新](install-guide.zh-CN.md)准备宿主，再导入本次本地交付的 `.tgz`。成员资料读取与修改请看 [0.4.1 工具合同](tool-decoupling-0.4.1/TOOLS.zh-CN.md)，本文其他成员、参数、记忆与试演操作继续适用。

## 开始使用

打开一个角色聊天，点输入框旁的“角色团队”入口打开团队侧栏。没启用时，“本轮”页会显示“启用团队”按钮；侧栏右上角的开关也能随时启用或关闭。开关立即生效、只影响当前聊天，不需要保存；取消启用会让下一轮恢复普通 RP。

团队侧栏有五个页签：

| 页签 | 用来做什么 |
|---|---|
| **本轮** | 这一轮的结果（一句话 + 参与人数、请求数、Token、用时）；“谁参与了”逐个列出成员、怎么进来的、用了什么模型，没参与的成员写明原因（例如“每 2 轮运行一次，本轮不在周期上”“只在某成员调用时运行”）；已保存到聊天的正文；“打开完整轨迹”；页面底部预告“下一轮谁会运行”。失败或取消的一轮，重试按钮就在结果旁边。左右箭头切换前后几轮。 |
| **队伍** | 分三块：**成员**、**使用参数**、**团队设置**。点一名成员进入它的六个页签：提示词、模型、何时运行、能看到、协作、权限。侧栏够宽（约 720px 以上）时变成“成员栏 + 编辑区”并排。提示词可点“专注编辑”占满侧栏。 |
| **预设** | 当前预设的导出与存入预设库；从文件或示例替换草稿；本机预设库；成员组件。 |
| **试演** | **检查配置**：填一句假设的下一条消息，不调用模型，查看哪些成员会运行、各自能看到什么。**试演**：调用真实模型，按场景连续运行并比较两个方案。 |
| **状态** | 当前聊天的状态值、记忆集合和过去的状态。 |

队伍页里的修改先进草稿：头部显示“未保存”，改过的成员在列表里带点，侧栏底部出现保存条，列出改了哪些成员、参数和团队设置，点名字可以跳过去。点“保存”后从下一轮开始生效；“放弃修改”需要再点一次确认。导入的预设和载入的示例同样先进草稿。

“检查配置”不请求模型。“试演”会真实调用所选模型，因此会产生相应的服务商用量；只有点击“开始试演”才会开始。作者自行编写连续几轮的输入和检查条件，软件不会代替作者编造用户行为或判断哪种 RP 更好。

## 试演与方案比较

先选好要冻结的聊天资料，再点击“冻结当前聊天资料”。试演有自己的进程、DSH profile、Session、数据库和工作目录；正文、状态和记忆不会写回正式聊天。

方案 A 使用当前团队草稿。可以再选方案 B 与 A 比较。两者依次运行，各自从同一资料快照开始；方案 A 累积的状态、记忆和正文不会进入方案 B。比较结果呈现实际正文、状态差异、成员运行、用量和耗时，不替创作者给作品打分。

关掉右侧面板不会停止任务。停止按钮会取消并排空正在执行的调用。若应用或试演进程意外中断，任务标为中断；明确重试时从最后成功提交的试演轮次继续。未能从服务商取得完整 Token 用量时，开启 Token 上限的任务会提示“用量不可计量”，并停止后续模型请求。

默认每轮最多 32 次请求、64,000 个服务商报告 Token、180 秒；整个任务最多 64 次请求、128,000 个 Token、600 秒。可以在开始前调整。在途请求可能在停止前继续消耗，因此 Token 上限不能当作精确费用封顶。

默认只允许托管工具和试演工作目录。若确实需要外部工具，需要在**本次试演**单独开启信任；那类工具对试演目录以外的文件、网络和程序造成的影响不属于隔离范围。

试演结果页的“查看真实运行轨迹”打开宿主同一套轨迹界面，可以展开每个模型请求的实际输入、模型回复、工具参数和结果。试演轨迹不会混进正式对话正文。

## 设定可调参数

在“队伍 → 使用参数”里，普通使用者可以通过表单调整创作者公开的选项，例如语气、温度、触发间隔或初始状态。每个聊天单独保存自己的使用值，不会改动原始分享预设。移除某项参数后，旧值不会绑定到其他设置。

创作者可定义文字、数字、开关、选项、成员、模型和状态位置七种参数。一个参数可以绑定成员稳定 ID、已有设置字段或指定的提示词插入位置。缺失的成员、模型或状态会明确提示修复；系统不会暗中替换成另一个值。每轮开始时固定本轮参数和解析后的配置，途中改草稿不会改变已开始的执行。

### 像预设条目一样切换的设置（0.7.0 起）

文字、数字、选项和开关参数都能用「替换提示词中的参数标记」绑定，把内容放进成员提示词里写着 `{{param:参数ID}}` 的位置：
- **文字**：放进使用者填的文字。
- **数字**：放进这个数，例如「正文约 {{param:字数}} 字」。
- **选项**：创作者给每一项写好一段「选中时插入的文字」，使用者从下拉框选一项，就换成那一段。例如文风选「白描」「细描」「口语化」，或者现实尺度选「严：拒绝不合理的要求」「宽：为用户的要求找补」。
- **开关**：创作者写好「打开时插入的文字」和「关闭时插入的文字」，留空表示不插入。效果和酒馆里打开、关闭一个预设条目相同。

参数可以填「分组」，同一组的参数在使用参数页放在一起，例如「呈现」「裁定」「运行」。选项和开关下方的「查看插入的文字」显示当前这一档会放进提示词的原文。

用了这些功能的预设，导出时会标明需要插件 0.7.0 或以上。

## 事件与节奏

除了每轮执行、手动选择、被成员请求和结构化条件，还可以设置：每隔 N 个有效用户轮次、某状态值发生变化、收到指定成员或类型的消息、当前输入包含指定关键词。可为规则添加冷却轮数。

触发会遵循成员已有的信息权限。例如无权读取当前输入的成员不会靠关键词规则获知内容；无法查看某状态的成员也不能靠状态变化触发获得状态细节。只有本轮正文成功提交后，冷却才记一次；失败、取消与正式回退不会错误地消耗冷却。保存作者状态不会启动后台模型。

## 记忆

创作者在“状态”页里把一个列表定义为记忆集合，并决定它属于共享、世界还是某个成员的私有状态。成员通过搜索、新增、修改、归档和恢复工具操作记忆。搜索先应用读取权限，再匹配和计数，因此无权查看的记录不会泄露在搜索结果中。

内容、人物、标签、来源、时间、视角、可信程度和自定义字段都可组合。可分别保存客观事实、角色信念和角色回忆；框架不会擅自纠正它们或偷偷调用模型整理。成功提交后记忆才保存，冲突或失败会保留清楚的结果，回退会跟着状态检查点恢复。预设分享包包括集合定义和作者初始值，不包括某个聊天积累的记忆。

## 查看轨迹和常见问题

聊天正文保持简洁。团队生成的回复下方有一个“协作概览”链接，点开先落在团队侧栏的“本轮”页，看这一轮的结果和参与的成员。要看细节时：展开一名成员，点“查看请求详情”，主聊天的“轨迹”页会直接定位到这名成员的执行；点“打开完整轨迹”则从这一轮开始逐条查看。轨迹页显示真实 Agent Loop 步骤、成员执行、模型请求、回复、工具和压缩，顶部可以按成员筛选，“清除筛选”恢复全部。轨迹不会作为辅助正文插入聊天。

- **为什么这一轮只有一名成员运行：**看“本轮”页“谁参与了”里没参与的成员，每人都写了原因，例如按周期运行的成员这一轮不在周期上，按需成员没有被调用。页面底部还会预告下一轮谁会运行。

- **看不到旧聊天的 Agent Team 步骤：**试演和新版本开始执行后会记录完整关联；无法可靠确定来源的历史记录不会按时间猜轮次。
- **Token 预算未启用：**正式聊天保留旧行为。试演默认启用独立的轮次和任务预算。
- **服务商不报告用量：**若设了 Token 上限，团队会保守停止后续请求并提示无法计量；它不会用估算值假装准确。
- **普通聊天如何恢复：**关掉团队侧栏右上角的启用开关，下一轮会走原来的聊天路径。
- **失败的一轮为什么没有重试按钮：**重试只能沿用这一轮当时的输入和团队配置。团队已关闭，或者这一轮之后保存过不同的配置，“本轮”页会直接写明原因，不再提供重试；这时直接重新生成这条回复即可。只是关掉再打开团队、配置内容没变的，仍然可以重试。
- **预告里写“冷却中”：**设了冷却轮数的触发刚触发过，要等冷却结束才会再次触发；预告会写出从第几轮起可以再触发。
- **启用时提示“没能切换团队开关”：**宿主拒绝了切换，通常是某名成员的模型不可用。到“队伍”里检查成员的“模型”页签，再重新打开开关；提示可以点右侧的叉关掉。
- **组件或预设怎么分享：**导出只含配置、作者参数声明、初始值和依赖，不包括凭据、历史或运行日志。

需要编写自定义认知架构时，请读[完整预设作者指南](authoring-0.4.0.md)。
